# prompts/

**提示词的唯一存放处。** 代码里不允许内联提示词 —— 由 `.githooks/pre-commit` 与测试强制。

## 为什么单独放

1. **提示词是这个项目的"游戏逻辑"**（见 doc/DESIGN.md：「提示词 = 作者控制 AI 的代码」）。
   它改动的频率和重要性都不低于代码，混在字符串里没法评审、没法 diff。
2. **将来做卡系统时，卡要能覆盖它们** —— 文件是天然的可替换单元。
3. 排版干净：源码里写 `\n` 拼接的多段文字，在这里就是普通的 Markdown。

## 怎么被加载

`src/core/prompts.ts` 用 Vite 的 `?raw` 在**构建期**把文件读成字符串：

```ts
import 系统提示词 from '../../prompts/system.md?raw'
```

所以没有运行时 fetch、没有额外请求，构建产物和以前一样是单个 JS。

## 占位符约定

`{{名字}}` 由代码填入。**填不完就会抛错**（见 `renderPrompt`）——
提示词与代码的参数对不上时快速失败，不把 `{{SNAPSHOT}}` 这种字样发给模型。

| 文件              | 占位符                        |
| ----------------- | ----------------------------- |
| `system.md`       | `TOOLS` `CALENDAR` `SNAPSHOT` |
| `tools.md`        | `SEGMENTS`                    |
| `tool-results.md` | `RESULTS`                     |

## 边界：什么算「提示词」

判据是**这段文字发给谁**：

| 发给谁   | 放哪         | 例子                                             |
| -------- | ------------ | ------------------------------------------------ |
| **模型** | `prompts/`   | 系统提示词、工具说明、开场指令、工具结果外套文案 |
| **玩家** | 代码里直接写 | 错误提示、「存档已损坏」、「正在生成开场…」      |

给玩家的文案不是提示词 —— 它属于 UI。但为了不让人混淆，`.githooks/checks/prompts.mjs`
对超过 30 字的中文串也会报警，**给玩家的长文案要在行尾或上面两行加**：

```ts
// 允许：这是给玩家看的错误说明，不是给模型的提示词
;`本地存档已损坏，本次从空白开始…`
```

## 改提示词的注意事项

⚠️ **示例必须是「正确输出的完整形态」，不能是简化片段或占位符。**
模型跟着示例走，不跟说明走 —— 这条踩过两次，见 `doc/AGENTS.md` 与 CHANGELOG。

改完**必须用真实 API 验证**，不能只看逻辑通不通。这里有 143 项测试保证格式没坏，
但保证不了「模型会不会照做」。
