# 做卡系统：开发计划

> 目标：把项目从「一个固定玩法的游戏」变成「**一个能装很多卡的引擎**」——
> 作者写一张卡，就等于定义一个新游戏（世界观、人物、回合流程）。
> 设计内容见 `doc/DESIGN.md`（当前设计）；本文只写**怎么落地、按什么顺序、每步怎么验收**。

## 两条已定的实现决策

1. **事务用工作副本**：一轮开始时 `structuredClone(state.data)`，节点只改副本，
   跑到终点才写回 `state.data` 并落盘；失败/取消丢弃副本（内存与存档都不留痕）。
   备选「节点只产生事件、提交时回放」更纯，但要额外写回放器，暂不采用。
2. **图的画布只在 dev 里用 vue-flow**：`@vue-flow/core` 作为 **devDependency**，
   只出现在 Storybook / dev 页里，**不进 dist**（产品依赖仍然只有 `vue`）。
   卡图的可视化是作者/调试工具，不是玩家功能。

## 阶段

| 阶段 | 做什么 | 验收 |
| --- | --- | --- |
| **0（已完成）** | 合并 main 的卡与文档、文档归位 | 内容零丢失、无死链、271 项测试全过 |
| **1a** | 依卡格式评审的结论**最小改动**卡格式（补 schema 声明、稳定 id、版本号、内容/呈现分离这类） | 你过一眼改动集（动卡是唯一需要你确认的地方） |
| **1b** | `src/game/card.ts`：形状校验 + 图不变式（边指向存在的节点 / 无环 / 必须有终点 / 节点输入只能来自上游） | `cards/morningwind.json` 必须过；自造反例必须被拒 |
| **1c** | **卡图查看器**：Storybook story，用 vue-flow（devDependency）画节点、边、每个节点的输入来源 | 有截图基线（`npm run stories`）；字段问题看图就能看出来 |
| **2** | `snapshot()` 升级为「按节点声明裁剪上下文」（公共部分 + 上游累加） | 默认单节点时输出**逐字节不变** |
| **3** | `src/agent/graph.ts`：照图跑的通用执行器；`runTurn` 内部改用它，**默认图 = 1 个节点** | 271 项测试全绿 = 玩家体验零变化 |
| **3b** | 卡图**运行时高亮**：跑到哪个节点、哪一步失败、是否回滚，都在图上标出来 | 真机截图能看到高亮；调试时一眼定位 |
| **4** | 事务边界落到组合根（工作副本 + 提交/回滚） | 「失败不落盘**且内存回滚**」有专门用例 |
| **5** | 回合生命周期状态机显式化（`prompting / executing / forcing / finishing` + `committed / rolled-back`） | 迁移表**正反用例**：合法全过、非法全拒 |
| **6** | 显示层由卡驱动（DESIGN #15）：浮层按卡的声明渲染，替换现在写死的三块 | 侧栏/浮层由卡声明生成；重录像素基线 |
| **7** | 至少再写**一张不同形状的卡**（有分支 / 没有 NPC / 别的世界观），用它证明格式与执行器不是只为《晨风镇》写的 | 新卡能过校验、能跑一回合；渲染器与校验器**不认识具体字段** |

## 每轮都要做的（门禁）

- 新增功能 → 新增测试（钩子强制：新增源码必须在 `tests/` 里有对应引用）
- 改到界面 → 跑 `npm run visual` / `npm run stories`（pre-commit 会按改动提醒）
- 设计有变 → 更新 `doc/DESIGN.md` 决定表（**从 #25 起编号**）与 `doc/CHANGELOG.md`
- 提交信息用约定式前缀（**不接受 `merge:`**），全量把关 `npm run verify`

## 明确不做

- 不把图执行器写成一堆 `if`：节点类型是**判别联合**，非法的组合用类型排除
- 不让卡定义「引擎怎么跑」：卡只声明**有哪些节点、谁给谁数据**；
  遍历、事务、回滚、取消这些**规则**在引擎里，且只有一处
- 不引 xstate（项目运行时依赖只有 `vue`）；生命周期状态机手写迁移表 + 纯函数
- 不给「世界演化」写死状态（DESIGN #9：流程由卡作者写死）
- **不追求一次做完**：每个阶段单独可验证、可回滚，阶段 3 之前玩家看到的界面必须**零变化**
