### 新增
- **改了东西却没记更新日志，提交期会拦下（票 54）** —— 这条纪律**以前没有任何检查兜底**：
  2026-09-16 实测漏过两条（合进 main 的三条改动里，只有一条自己写了更新日志），
  是用户翻本文件才发现的 —— 按项目自己的原则「写不出谁强制它的规则，就是建议」，
  给它配了机器检查。**判据**：暂存里有 `src/` 或 `cards/` 开头的文件（**两条线**：卡是内容，
  改了就是改了行为）、却**没在本文件的未发布段记一笔**时，`feat` / `fix` / `perf` **拦下提交**，
  其它类型**只提醒**（提醒永远跟着这件事打，与拦不拦无关，且给出下一步）。
  **逃生口** `CHANGELOG: none —— <理由>`（破折号必须是两个 `——`，**理由不许空**；
  空的与写成 ASCII `--` 的都不算声明）。**"记了一笔"按内容认**：diff 里只动了空白**不算**。
  **本分支自 merge-base 起记过一次就够** —— 同一支上的后续提交不必再记（一次提交净增
  上限 500 行，稍大的改动必然拆成两三笔，否则每笔都要写一句理由，纪律当场变仪式）。
  **边界**：约定式提交的破坏性变更写法 `feat!:` / `feat(scope)!:` **类型仍是那三类** ⇒ 一样拦，
  而 `chore!` / `docs!` 仍然只提醒；**合并提交放行**；`tests/` · `doc/` · `.githooks/` 都不算
  「改了东西」。**git 自己跑不起来时宁可拦住也不放行** —— 实测踩过一次「一律放行」：
  子进程起不来时 `execSync` 抛的 `status` 是 `null` 而不是 `undefined`，按它分辨不出
  「git 没输出」与「git 没跑起来」，于是暂存区看着是空的、每一次提交都被放行。
  **形状**：判定是**纯函数**（不读文件、不读 argv），另有一层**命令行薄壳可单独跑**
  （`--message <路径>` 把这次的消息路径从实参拿，**绝不读那个固定的「本次提交信息」文件** ——
  合并那一次它里面是上一次的旧消息）；挂 `commit-msg` 而不是 `pre-commit`，因为只有这一关
  拿得到**这一次**的提交信息。判据 **34 条**：判定面 30 条（进程内直接调那个纯函数）+
  接线 4 条（**真起一次 `commit-msg`**，断言退出码与输出）。
- **提示词资源面板：卡里那几块原始提示词看得见、改得动（票 56）** —— 卡编辑器表头多一颗
  「提示词资源」按钮，点开列出卡里的**全部资源**：五块设定（世界 / 核心 / 常见 / 风格 / 主控）·

  存储与内存里那张卡一个字节不动；**正文被清空会被拒并说清原因**（行数组收得下一行空串，
  所以这一判在进校验器之前做）。

  删掉**（卡格式里「不写」就是五块全发 / 不带生成器，空表会被校验器拒）；设定列最后一块不可取消
  （空 `settings` 表达不出「什么也不发」）。勾选只动它自己那一列。

### 修改
- **卡格式 card/4：类型表 8 → 6，而且「必填」没有了**（票 59）—— 老板原话：「8 种 schema 太多太复杂了，
  我都搞不懂，卡作者更搞不懂」「没有"必填"这个东西了」。八种类型里 `number` 与 `boolean` **卡里一处都没用到**、
  「必填」也**一次没标过** —— 三样都是纯负担，所以：
  - **类型词汇表只剩六个**：`string` / `integer` / `enum` / `list` / `map` / `object`（能写成裸字符串缩写的只有
    `string` / `integer`）。卡里写 `number` / `boolean` ⇒ **载入失败**，错误信息带 `state.…` 路径。
    **不做别名兼容**（`number` 不会悄悄映射成 `integer`）—— 旧卡就该报错。
  - **`required` 从 schema 语言里整个删掉**：写它 ⇒ 当**未知键**拦下。于是 merge 写入的「必给」
    只剩一件事：**一个都不必给**（工具参数的 `required` 是 `[]`）。⚠️ **模型现在理论上能报一个空 patch，
    这是有意的**、不是漏的（`set` 那种整条替换不受影响：每一栏照旧都得给）。
  - ⚠️ **同名不同义的那一个没动**：**工具参数**（JSON Schema）里的 `required: string[]` —— map 的键、
    push 的 `value`、内置效果（`advance_time` / `redo`）—— **一处都没碰**，判据钉着它。
  - **格式戳提到 `card/4`**，连引擎常量与**三张卡的元信息戳**一起走（卡的内容一个字没改）。
    **旧 `card/3` 存档载入失败** —— 不做版本迁移，这是既有的取舍。
- **钩子的语法检查补上漏掉的文件**（票 58）—— `.githooks/` 整目录在"源码纪律"那一步被豁免，
  语法检查跟着一起没了：三个钩子入口（`pre-commit` / `pre-push` / `commit-msg`）与 `checks/` 下的脚本
  **一个都没被检查过**。改成按目录取（`.githooks/` 下的脚本全进），钩子自己的语法从此有人管 ——
  钩子里一个语法错挡的是**所有人的提交**，而没人会想到去查钩子。
- **模型的记忆放宽到「开局以来的全部故事」（票 57）** —— 原来两处上限把故事截了：发给模型的
  「最近发生的事」只取**尾部 8 条**（≈ 最近四轮），存档里故事留 **80 条**（≈ 40 轮）。
  用户拍板：「每轮故事才几百字，我要**从开局到现在的所有完整故事记录都保留**，你别管 token 成本，
  以后再考虑压缩的事情。」⇒ 两处上限都**去掉**（**不是调大** —— `RECENT_STORY` 与 `MAX_STORY` 都删了，
  将来谁想恢复「只发最近 N 条」都得重新写一个常量、绕过不了判据）。
  **模型记忆 = 这一轮之前的每一条故事事件**：一条不少、顺序不变，仍然只到 `memoryUpTo` 为止
  （这一轮的原话在「玩家」段里）；**存档的写入与读档两条路都不再丢故事**。
  **调试那一路照旧**（仍只留最近 **120** 条、仍丢最旧的，写入与读档同一条判据）——
  放宽故事不等于「什么都不裁」，调试噪声挤掉模型记忆这件事仍然不许发生。
  顺带把那条段落的标题改成「**故事到目前为止**」（中英各一条：`prompts.recent`；旧名是"最近发生的事"），
  它罩着的早就不止"最近"了；`RECENT_STORY` / `MAX_STORY` 在决定 #50
  与 `types/state.ts` 的注释里也一并订正。
- **工具调用行 / 工具结果行的摘要收短 + 块清单默认全折叠（票 55）** —— 调试痕迹里的
  `⚙ 调用 <工具>(…)` 与 `   → <结果>` 两行不再把整段参数 / 整段结果铺在摘要行上：摘要只留
  **前 40 个字符**（正好 40 字不截断），超出的部分接一条省略号文案（`debug.previewCut`，中英各一条）。
  **收短的只是摘要** —— 完整参数 / 完整结果仍逐字写在那一行的折叠体里（`detail` 一个字节没动，
  「原始」那一折与调试面板读的就是它）。块清单（模型输入 / 模型原始回复）**进来时所有块都折叠**，
  要看哪一块点哪一块的标题条。
- **调试痕迹的「模型输入」「模型原始回复」按块渲染（票 53）** —— 这两行展开后不再是缩进 JSON 一坨：
  提示词按它**本来有的段**分块（设定各块 / 剧本 / 规矩 / 生成器 / 现在 / 玩家 / 上游 / 本节点提示词 /
  重跑提示），**一条消息一组**，每块标题条上标出字数，点标题条开合（默认所有块都折叠）；
  块内**逐字保留换行**（空行也是一行）、`### ` 行按小标题画出来、长行自动折行不撑破版面。
  回复那侧分「模型说的话 / 它申请的每个工具调用（工具名 + 参数原文）/ 其它（结束原因、用量…）」。
  块的边界与行结构由**装配器**交出（`requestBlocks` / `replyBlocks`），界面一行文本都不切；
  两块都跟着存档来回（`GameEvent.blocks`），**旧存档**没有这个字段就按原始文本显示。
  接口原样的 JSON 仍在每行里一个可折叠的「原始」里 —— 好看没有把调试价值换掉；
  **发出去的请求体一个字节都没变**（拼回来的提示词与发出去的那条逐字节相等，有测试守着）
- **节点可以声明自己读哪几块设定（决定 #52）** —— 节点新增可选字段 `settings: string[]`：
  **写了 = 只发这几块，没写 = 五块全发**。示例卡里七个节点声明 `["world","core","common","lead"]`，
  `outline` / `story` 两个节点不写 —— 于是「文字风格」那 33 段原文**只给写大纲和写正文的节点看**，

  **筛、不重排**（用户写的顺序不影响块的先后）；声明了卡里没有的块名、空表、重复块名**加载即失败**
- **卡里的「文字风格」块换成 33 段原文范例** —— `settings.style` 从 10 段 1458 字扩到 **33 段 5163 字**：

## [0.5.4] - 2026-09-12

### 修复
- **时间线（侧栏那块）从来没正常显示过** —— 两个 bug 叠在一起：
  - 每条记录的**起点写成了终点**（`from === to`），起止失去意义
  - 记录门槛是「跨度 ≥ 6 小时」，而默认单位 `segment` **固定就是 4 小时**
    → 默认推进**一次都进不了时间线**
  - 现在门槛降到 4 小时，起点用推进前的时刻
- **`describeElapsed` 的时长换算会算错天数**
  - 原先 `days % 365 / 30` 配 `days % 30`，而 `365 = 12 × 30 + 5` ——
    两个取模都从「年」里吃天数，**每满一年就凭空多出 5 天**
    （365 天→「1 年 5 天」、730 天→「2 年 10 天」）
  - 改成**先年、再月、最后天**逐级剥离，谁都不重复吃
  - 顺带补上单位之间的空格（原先会连成「1 个月1 天」）
  - 实测：365 天→「1 年」、400 天→「1 年 1 个月 5 天」；
    19 个采样点折算回天数**全部吻合**
  - 并在注释里写明：这是**时长换算**（1 年按 365 天、1 月按 30 天），
    不是日历跨度 —— 只拿到差值，本来就无法精确表达日期差
- **时间线渲染的是终点，修好的起点根本看不见**（`index.html`）
  - 数据里 `from` / `to` 都对，界面却只渲染 `to` —— 和侧栏上方的大字时间重复，
    也看不出「从什么时候起发生了什么」
  - 改成渲染 `from` + 原因：`↑ 9 月 12 日 · 上午` ／ `睡了一觉到第二天`
  - 终点不必在这里重复，上面的「时间」已经是它了
- 页面刚打开时会闪一下早废弃的「第 1 天 · 上午」（硬编码初始文案），
  改成中性的「载入中…」

### 说明
- 复检发现（**不是 bug，已确认兜底正常**）：`calendar.advance` 收到非法时间会抛
  `RangeError: Invalid time value`，但 `state.advanceTime` 有 try/catch 兜住，
  返回警告文案而不是崩溃。这条路径只在存档被人工篡改时才会走到。

### 加固（一次独立代码审查的产出）

发布前把一个独立审查员放进来重新读全部代码，它找出并**逐条实测复现**了一批缺陷，
下面这些已修：

- **回合可以并发跑**（`index.html`）—— 模型正在写故事时点「重来」或「导入」，
  会同时跑两个回合：旧回合的 `addLog` / `advanceTime` / `save` 全作用在**新游戏**上，
  于是新存档里混进旧剧情、回合数对不上；「设置→保存」连点两次还会重复开场、双倍额度。
  现在加了重入保护，且换 state 之前先中止在跑的回合。
- **工具名撞上 `Object.prototype`**（`tools.js`）—— `TOOLS[name]` 对
  `constructor` / `toString` / `valueOf` / `__proto__` / `hasOwnProperty`
  会取到原型上的**真值**，绕过「没有这个工具」的判断，随后抛 TypeError；
  异常穿出 `runTurn`，`endTurn` / `save` 全不执行 —— 玩家看到的叙事不落盘、
  时间却已经改了。改用 `Object.hasOwn`。
- **认不出的时间单位被当成 reason**（`state.js`）—— 模型很爱写复数，
  而 `unit:"days"` 会被当成「reason」、单位退回 `segment`：
  **推进量错算成 4 小时**，模型给的原因被顶掉，时间线里永久记着 `reason:"days"`。
  现在认不出就明确报错，并加了别名表（复数 / 中文 / 大小写）。
- **解析器静默吞内容**（`tools.js`）—— 同行围栏（` ```tool {...}``` ` 不换行）
  解析不出工具块、还会把裸 JSON 当正文显示；解析失败的块既不报错也不提示，
  整块从正文消失。现在支持同行围栏、失败一律出声、非工具的 json 数据块**保留**。
- **脏存档会让游戏永久卡死**（`state.js`）—— `normalize` 原来只判「是不是数组」：
  非法 `iso` 会让侧栏永久显示 `NaN 年 …` 且**唯一的工具每次都失败**；
  `log` / `timeline` 里有一个 `null`，`snapshot()` 就抛 TypeError，
  而它在拼提示词阶段调用 —— 此后**每一回合**都在同一处崩，且 `save()` 在抛错点之后，
  坏数据永远不会被覆盖修复。现在逐项过滤校验，`turn` 也强制成数字。
- **`dev-server` 的黑名单可被大小写绕过**（`dev-server.js`）—— Windows 文件系统
  不区分大小写，而比较区分。实测（修复前）：`/DEV-SERVER.JS`、
  `/README.MD`、`/PACKAGE.JSON` 全部 **200**，`/.GIT/config` 甚至能直接读出
  仓库的 git 配置。虽然只监听 `127.0.0.1`，但过滤逻辑是失效的。
- 另外三处小的：网络报错后顶栏红灯不复位；「测试连接」成功却不刷新顶栏
  （玩家会以为配置失败）；接口返回非 JSON 错误（HTML 502）时拿不到任何正文
  —— 因为 `res.json()` 失败后再 `res.text()` 必然抛错，被吞成空串。

**已知未修**（记在 `AGENTS.md` 待办，不影响本次发布）：
失败/取消路径的内存与存档分叉、步数上限误报、时长文案丢掉小时、
`month` 单位月末溢出、时间线只显示起点（这是**有意设计**，非缺陷）。
