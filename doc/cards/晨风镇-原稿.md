## 2. 给 AI 的四块设定

**四块都是自然语言，不是变量字段。** 三个理由：

| 为什么 | |
| --- | --- |
| **它本来就是提示词** | 跟各个节点的提示词是同一类东西 —— 都是「作者控制 AI 的代码」 |
| **字段名永远不够用** | 「有没有神」「种族关系」「科技水平」「死人会不会变成鬼」…… 列不完，列完了就是又一份要维护的 schema |
| **光有标签没有信息量** | 只写「中魔」两个字没用 —— **每个模型对"中魔"的理解都不一样**。有用的是一段解释 |

**四块都进每个节点的上下文**，按 2.1 → 2.2 → 2.3 → 2.4 的顺序排在最前面。

> 💡 **为什么要拆**（2026-09-14 用户分两次提出）：
>
> 先把「客观信息 / 叙事风格 / 主控设定」拆开 —— **三种东西的改法不一样**：
> 事实不能随便改，风格是作者的口味，主控设定决定了玩家能不能代入。
>
> 再把「客观信息」一刀两断（**用户第二次提**）：
> **社科**（有多少人、谁在收税、路通向哪儿）和**核心要素**（魔法是什么、谁能用、代价是什么）——
> **这不是一类东西。核心要素是这个世界的"物理定律"；社科是"住在这个定律里的人间"。**

### 2.1 「世界设定」—— 社科（2026-09-14 拆出）

**这个世界的人间**：它在哪儿、谁在管、靠什么活着、有多少人。

```text
【地理】
一片叫「塞尔」的大陆（名字待你定）。用的是现实历 —— 有星期、有月份、有四季。

晨风镇在**赫兰王国**的东北边陲，背靠雾岭，一条土路往南通向官道。
- 出镇往北 → 雾岭。再往里，没人去
- 出镇两小时脚程 → 地牢入口（在雾岭的坡上）
- 沿官道往南，**两天马车** → 王都「赫兰」
- 沿途还有几个镇子，但**晨风镇是最靠北的一个**

【政治】
**赫兰王国**。国王年迈，膝下只有一个女儿 —— 就是被掳走的那位。
朝里两派：**老臣**守着旧规矩，**军功新贵**嫌分得少。

⚠️ 对晨风镇这种边陲小镇来说，王国的存在感**只有两样**：
一年来两次的税吏，和镇公所门口那块布告栏。

【经济】
- **晨风镇**：伐木 + 给过路商队补给。赚的是"过路钱"，镇子不富
- **硬通货**：铜币 / 银币 / 金币
- ⚠️ **一枚金币在晨风镇是大钱** —— 够一家人吃半年。别随手写"十个金币"
- 冒险者公会的委托，是镇上唯一的"暴富"路子 —— 这也是有人肯下地牢的原因

【人口】
晨风镇**三百来口人**，人类为主。精灵和龙族**几代才见一个**，来了就是全镇的话题。
识字的人不多（神殿的老祭司教几个孩子认字）。
**大部分人一辈子没出过雾岭** —— 所以"去王都"对镇民来说是件大事。
```

### 2.2 「核心要素设定」（2026-09-14 新开）

**这个世界的"物理定律"**：什么力量存在、谁能用、代价是什么。

> 它跟 2.1 分开的理由：**它是这套世界观的发动机** ——
> 魔法怎么运作，会一路决定治疗、战斗、地牢、队友能干什么。
> 改它的动静，比改"镇上有多少口人"大得多。

```text
【魔法】**中魔**：魔法真实存在，也有靠它吃饭的人 ——
但它是**专业技艺**，不是日用品。

- 会施法的人少，**能熟练使的**更少。晨风镇一个都没有，最近的法师在三十里外的塔里
- **慢、贵、有代价** —— 没有"随手一挥"这回事
- 街上看不到魔法，但它**确实会发生**：你总有一天会亲眼看见
- 魔法物品大多是祖传的、有来历的，不是货架上的商品
- 地牢里的魔法造物，一定有"谁做的、为什么留在这儿"的解释

⚠️ **施法很累 —— 而且没有"法力值"这种东西。**

不是"还剩多少点"，是**真的会累**：手抖、耳鸣、想吐、得坐半天才缓过来。
你要是让一个法师连放十个火球术，他会当场骂你：

> 「很累的，你懂不懂魔法啊？放十个火球术你想让我直接榨干吗？」

所以：**法师不是炮台，队友也不是你的技能按钮。**
他们的累要写在**他们的状态里**（手抖、脸色发白、靠墙坐着喘），
**不是写在一个数字里**。

【治疗】⚠️ **没有"一键回满"。**
治伤靠三样东西**一起**：**药材 + 护理 + 时间**。
魔法只能**加速**这个过程 —— **跳不过去**。

照这个感觉写（**例子比规则管用，下面这几条是范本，照着仿**）：

- 镇上唯一的药师会配一种黑乎乎的膏药。敷上三天，刀口就收口了 —— 疼，但管用。
- 神殿的老祭司会一手"按手"：他按住伤口念一段话，血就止住了。
  镇上人都说那是女神显灵 —— 其实那是他年轻时跟军医学的止血手法，加一味嚼烂的草药。
  **他从来没纠正过这个误会。**
- 酒馆二楼住着个退役军医，专治箭伤。他不念咒，只用刀、线和烈酒。
  收费比谁都贵 —— 因为救活的人比谁都多。
- 三十里外塔里那位法师，据说能把断骨接上。代价是先付十枚金币，
  而且他会让你睡过去，醒来时**已经过了三天**。
- 传说地牢深处有一口泉，喝了它伤口好得飞快。有人赌咒说喝过，也有人说那是骗人的。

【种族】这个世界上不只有人 —— 而且**族类比谁记得住的都多**。
精灵、龙族、哥布林、亡灵族，这些只是**见过的**：

| 种族 | 在这儿的境况 |
| --- | --- |
| **人类** | 绝大多数 |
| **精灵** | 长寿、尖耳朵。**活得久，学过的东西就多** —— 会一两手简单魔法不算稀奇（**一样会累**）。罕见，出现一个就是全镇的话题 |
| **龙族** | 有龙的血脉，力气和皮肉都硬得离谱（**一个能顶几个成年人**），但**不是龙** —— 没有龙息、不会飞。**简单魔法是血里带的，顺手就能使 —— 也顺手就会抱怨累**。混在人群里做手艺活、当佣兵、跑商队。极罕见 |
| **哥布林** | 镇上没有，**地牢里有**。会说话、会跑、会记仇 —— **不是刷经验的木桩** |
| **亡灵族** | 存在，但**死掉的人不会变成他们**。他们是活的、会累、会怕、会做买卖的一族；因为少见，走到哪儿都被多看两眼 |

> **种族主要影响"这个人看起来是什么样、别人怎么看他"。** 龙族是唯一的例外（体力上确实强）。
> ⚠️ **死人就是死了，不会变成亡灵。** 亡灵族是一个**族类**，不是"死掉的人"。

⚠️ **上面那张表是例子，不是清单。**

你需要一个合适的角色时，**可以随手长一个新族类** ——
魅魔、蜥蜴人、奇美拉、史莱姆娘、天使……想到什么加什么。

只要守两条：

- **符合这个世界的调子**（中魔、边陲、大部分人一辈子没出过雾岭）——
  所以新族类出场时，**镇民会盯着看**
- **别加得让世界变味**（这是冒险故事，不是马戏团）
```

> ⚠️ **为什么专门压住魔法那一段**：模型的默认先验是**高魔 D&D**（法术满天飞、魔法物品遍地）。
> 「中魔」离那个先验只差一步 —— 不写清楚边界，它会自己往"随手一挥"的方向跑。

#### ✅ 治疗的定位（2026-09-14 定）

**曾经担心过"没有治疗术，冒险会不会太难" —— 答案是：治疗术有，但它是"加速"，不是"跳过"。**

> ⭐ **它跟「没有 HP，只有伤势」是同一条设计的两面** ——
> **伤势之所以有意义，正因为它不能凭空消失。**
> 治疗术允许存在，但**只能加速愈合或止疼**；要是有一贴就好的东西，"左臂骨折"就只是个装饰。

**所以地牢的节奏还是紧的**：挨了重刀，该回城养还是得回城养 —— 只是能少躺一半时间。

| 手段 | 效果 |
| --- | --- |
| 草药 · 包扎 · 静养 | **基线** —— 慢，但哪儿都有 |
| 资深魔法师 · 神殿仪式 | **加速愈合 / 止疼** —— 贵、慢、要条件 |
| 地牢深处的"那口泉" | 传说 —— 真有假有，由生成器去长 |

### 2.3 「叙事风格」

**这张卡该怎么写**：基调、笔墨、往哪儿使劲。

**跟 2.1 分开的理由**：事实不能改，**风格可以调**。

```text
基调：冒险者地牢、成长、一点点悬赏的功利心。

这是一片美人不少的大陆 —— 主控是个年轻男人，路上会遇到很多人，
其中值得记住的，大多是年轻女人。「认识人」是这张卡的乐趣之一，不是背景板。

这个世界里的姑娘长什么样、身段如何，该写清楚的地方就写清楚 ——
主控是个年轻男人，他看人是有眼睛的。别写成生理课本，也别假装没看见。
```

> 💡 **这一块会被「精神分析」每轮微调** —— 作者定的是**基线**，
> 它按玩家当下的状态往下拨（见 §8 的 ⓪ 精神分析）。

### 2.4 「主控设定」

**玩家在世界里的那个身体**：他是谁、他能干到什么程度。

```text
⭐ 主控是个普通人。这一条最重要。

玩家是坐在电脑前的真人，主控是他在这个世界里的身体。为了让他能代入，
主控的本事不该突破常识：他能打赢，靠的是技巧、准备和运气，不是超人的力量。

他不会放火球术，不会一刀劈开石门，也不会越打越强到不像人。
（这个世界里**有**会放火球术的人 —— 但**主控不是其中之一，他也不会变成其中之一**。）
他变强的路是：更好的装备、更准的判断、更靠得住的同伴。
```

#### ⭐ 谁会死，谁不会（2026-09-14 定）

**用户原话**：*「别让人真死了，地牢里的怪可以死，或者被打昏 ——
毕竟我们的游戏是**线性叙事没有回档的选项**，关键角色的死亡是个**巨大的 discourage**。」*

**这条理由一次解释了三件事**：线性 + 不能回档 → **不可逆的失去 = 玩家的巨大挫败**。

| 谁 | 能死吗 |
| --- | --- |
| **主控** | ❌ **绝不** |
| **关键角色**（公主、队友、有名有姓的 NPC） | ❌ **绝不** |
| **地牢里的怪** | ✅ **可以死，也可以被打昏** |
| 无名路人 | ❌ 尽量不死 |
| **世界本身** | ✅ **会变** —— 政变会推进、公主会被转移、局面会变坏（见 §4.6） |

**判据很简单：有名字的就不会死。**

⭐ **「打昏」不是退而求其次 —— 它经常更好。**
被打昏的人可以审问、可以绕过、可以放走、可以在醒来之后变成仇人或者朋友。
**下杀手永远只是选项之一，不是唯一解法。**

⚠️ **执行者是「故事大纲」节点**：决定"这一轮演到哪儿"的时候，**不许把人演死**。
判定节点可以判出"这一击很致命"，但那一击要落成
**重伤 / 被俘 / 打昏 / 失去什么** —— 不是死亡。

**队友不受这条限制**：队友可以比主控强（龙族队友能顶几个成年人），
但**不能让他一个人杀穿** —— 他得是**一个有用的人**，不是替玩家通关的钥匙。

> ⚠️ **「普通人」是这张卡的选择，不是引擎的立场。**
> 别的作者完全可以做一张「玩家是龙傲天」的卡。

### 2.5 历法归谁管？—— 归引擎，不在这四块里

**历法是引擎字段**，因为 `calendar.js` 要照它算日期、`format()` 要照它排版。
它放在「开局」那一块（跟起始时刻是一对），当前值是 `real`（现实历）。

> 「我们用的是现实历」这句**同时**出现在两处，但角色不同：
> 引擎那份是**开关**（`"历法": "real"`），2.1 那份是**给 AI 的说明**
> （"用的是现实历，有星期、有月份、有四季"）—— 后者让模型知道该怎么描述季节和节气。
>
> 将来真要做自定义历法，那是 `calendar.js` 加一个预设对象的事 —— **现在不预留**。

## 3. 世界预设（作者写死的骨架）

**作者 100% 定「区域」；「地点」只列点名要有的，其余留给生成器。**

### 区域一：晨风镇

- **简介**：边境小镇，三百来口人，靠伐木和给过路商队补给过活。镇子不大，一条主街走到头。
- **必有地点**：醉猫旅店 · 萨伦铁匠铺 · 杂货铺 · 酒馆 · 镇口
- **态度**：⭐ **地牢是镇上日常生活的一部分** —— 人们谈论它、争论它、拿它下注、在酒馆里组队。
  **不是禁忌**（忌讳了，玩家就没法在酒馆认识队友）。有人下去发了财，也有人没回来；
  镇民把这当成「这行的风险」，而不是「不能提的事」。

### 区域二：镇郊

- **简介**：镇外两小时脚程的林地。越往深处树越密，鸟叫越少。
- **必有地点**：林间小道 · 地牢入口

### 区域三：地牢

- **简介**：没人知道是谁修的、修来做什么。
  **也没人知道它有多深** —— 下去过最深的人说自己到过"第九层"，另一个说那是他编的。
  **这件事本身就是地牢最勾人的地方。**
- ⚠️ **层数不预设**：玩家推进到哪儿，「生成器二」就长到哪儿。**别用旁白交代"总共几层"。**
- **公主在最深处** —— 这是**镇公所公告上写的**，而公告是**听人说**的。
  镇民**将信将疑**：有人赌咒说见过她，也有人说那三百金是拿来骗傻子下坑的。
- **第 1 层由作者预制**（见下）—— 它同时是**给生成器的样板**：基调、危险程度、格式，后面几层都照它来。

#### 💰 地牢里有什么值得拿（2026-09-14 定）

**⚠️ 这才是玩家下地牢的**主要动机** —— 不是救公主。**

| 东西 | 谁收 |
| --- | --- |
| **石壁上的苔 · 地衣** | 药师 —— 治伤、止血的药材原料 |
| **旧时代的铁** | **萨伦** —— 地牢里那些锈死的铁器，回炉是好钢 |
| **前人没带走的家伙** | 谁都收 —— 装备、钱、信件 |
| **怪身上的东西** | 公会 —— 水鼠皮、哥布林的牙，按件算钱 |

> ⭐ **这一格把核心循环闭上了：**
>
> ```text
> 下地牢 → 采到 / 打到东西 → 回镇卖给药师、铁匠、公会 → 换钱买装备 → 下得更深
> ```
>
> **它同时就是"没有等级的成长曲线"** —— 变强靠的是**装备和钱**，不是数字。
> 跟本卡已经定下的东西完全咬合：没有等级、没有经验值、状态里只存具体的东西。
>
> 💡 而且它给了每个 NPC 一个**收东西的理由** —— 玩家走进铁匠铺，萨伦有话说。

#### ⭐ 预制：第 1 层「沉水窖」

```text
主题      潮湿的旧水窖 —— 当年修地牢的人存粮的地方，现在大半泡在水里

简介      石阶尽头是一扇被撬开的木门。门后是齐膝深的黑水，水面浮着碎木
          和一片发霉的麻布。空气里有铁锈和陈粮的味道。

场景      门口石阶 / 水中通道 / 塌了半边的仓房 / 往下的铁栅门

敌意      一窝穴居的水鼠 —— 怕光，会成群扑上来抢干粮。不致命，但会丢东西
中立      一个比你先到的冒险者，蹲在仓房梁上拿绳子捞水里的东西。
          他不介意聊天，但不分你东西
友善      （第一层不放 —— 队友留到镇上的酒馆里认识）

通往下一层  那扇锈死的铁栅门**不再挡着路**
            （撬、砸、找钥匙、或者别的办法 —— 写成结果，不写方式）

前人痕迹  墙上有用炭画的箭头 · 一段断掉的绳子 · 仓房角落有人睡过的干草
```

> ⭐ **为什么第 1 层要预制 —— 它是给 AI 的样板。**
> 模型的默认先验是「阴森恐怖的地牢」（火把、白骨、低语、邪恶祭坛）。
> 你不给一个具体的样子，**它每一层都会往那个方向跑偏**。
> **一个样板胜过十条规则** —— 这也正是"示例是模型的行为模板"那条教训，
> 只不过这次示例不是写在提示词里，而是**写在世界里**。

## 4. 核心剧本（隐藏真相）

> ⚠️ **这一块 AI 知道，玩家不知道。**
>
> 而且**它必须先定好** —— 用户 2026-09-14 说得很准：
> *「模型写故事**太专注于眼前了**，很难自行规划这种涉及整个游戏的核心故事。」*
> 你指望它自己攒出一条贯穿全局的主线，它攒不出来。

### 4.1 三层真相

| 层 | 谁这么以为 | 内容 |
| --- | --- | --- |
| **表层** | 全镇 · 王国 · 玩家 | 一伙**邪教徒**掳走了公主，要献祭给邪神。悬赏三百金 |
| **中层** | 教团里**少数几个人** | 他们**拿了钱**，替一位大人物办事。至于那位大人为什么要公主，他们不问 |
| **真相** | （只有你知道） | **一位将军要政变。公主是唯一挡在路上的人。** |

### ⭐ 整张卡最重要的一条：**神不存在**

**女神不存在，邪神也不存在。**

世人**以为**他们存在（**真心以为**，包括那些虔诚的信徒），但**没有任何神会回应任何人**。

教团的"神力"，是**钱、组织，和对地牢的了解**。

> ⚠️ **所以真相只能靠「世俗证据」露出来** ——
> 不能靠"神不显灵"（那要玩家去验证一个否定命题），
> 只能靠**钱、笔迹、不该出现的东西、说漏嘴的人**。

### 4.2 那个将军（AI 建议，待你确认）

**为什么建议「将军」而不是「大臣」：**

| | |
| --- | --- |
| **他有兵** | 所以他**不需要**教团来造反 —— 他需要教团来**背锅** |
| **他是明面上的搜救人** | **主持悬赏、张贴告示、派人下地牢的人，就是绑匪** —— 这是全卡最好的一处张力 |
| **他不能直接杀公主** | 公主死在国内会引来调查；**"被邪教徒抓走"** 才是最干净的消失方式 |

**名字**：暂定**〔将军 · 待命名〕**（占位，你随时改）。

### 4.3 线索怎么露

**埋在游戏里的东西**（生成器和大纲节点按需取用，别一次全给）：

| 线索 | 指向什么 |
| --- | --- |
| 教团的仪式里**有不合教义的地方** —— 有人在改它 | 头目在**演戏**给信徒看 |
| 地牢里有**不该出现在这儿的东西**：一双好鞋、一块宫廷的料子 | **有人从上面来过** |
| **钱**：新铸的、成色一致的银币 —— 信徒不该有这么多 | **有人在养他们** |
| **一个动摇的信徒**：他真信，所以他开始发现不对劲 | 最有人味的一条线索 |
| 公主**没有受虐待** —— 她住的地方比信徒好 | 绑匪不想她死，只想她**消失** |

### 4.4 玩家什么时候该知道什么

| 阶段 | 玩家该知道的 |
| --- | --- |
| **开局** | 公告说公主被邪教徒抓走、关在地牢最深处。**没人证实过** —— 镇民将信将疑 |
| **下到中层** | 教团是**被人雇的** |
| **更深处** | 雇他们的是**上面的人** |
| **见到公主** | 她可能**已经猜到是谁**了 —— 但她没有证据 |

> ⚠️ **别急着揭穿。玩家自己拼出来，比 NPC 告诉他强十倍。**
> 大纲节点每次演到"该露线索"的时候，**露一条就够**，别一次给完。

### 4.5 玩家不管这条链的时候，它会自己走

**世界不等玩家。**

玩家跑去皇城当管家、和大小姐谈恋爱 —— **将军的政变照样在推进**：
公主可能被转移、被换个地方关、局面变得更糟。

**但底线是：不会走到"公主死了、这局白玩"。**
跟「主控不死」是同一条思路 —— **代价真实，但游戏永远还能玩下去。**

> 💡 机制上它正好落在已经定好的**惰性补算**上：
> 玩家回到某个区域时，把该算的算一遍。
> ⚠️ 补算要**有根据**（呼应已有的线索），**别凭空制造大事件**。

### 4.6 公主（AI 建议，待你确认）

**她不是等着被救的花瓶。**

建议：她**知道自己为什么被抓** —— 她手里有将军的把柄，**或者她本人就是那个把柄**。

**被关着的这段时间，她一直在想办法。** 玩家闯进去的时候，
她可能**已经快成功了** —— 也可能**已经失败过一次**。

## 5. 生成器（卡里的一等公民）

每个生成器 = `{ 适用 + 原则 + 输出 }`。**匹配顺序：具体 > 通用。**

### 生成器一 · 填充晨风镇

**适用**：晨风镇里还没有具体内容的地点与人物
**原则**：

1. 作者点名的五个地点**一个不少**
2. 其余店铺、住家**按需长**，别一次长满 —— 玩家逛到哪儿长到哪儿
3. **地牢是镇上日常生活的一部分** —— 谈它、赌它、在酒馆里组队下去。**别把镇民写成讳莫如深**
4. 物价按边境小镇算，**别出现金币级的东西**（一枚金币在这里是大钱）

### 生成器二 · 生成地牢新层

**适用**：地牢里尚未生成的层（玩家推进到哪儿，长到哪儿）

> ⭐ **先看第 1 层「沉水窖」—— 基调和格式都照它来。**
> 基调：**有年头、有人来过、危险但不致命**（不是阴森恐怖那一套）。
> 格式：主题 / 简介 / 场景 / 单位配比 / 通往下一层 / 前人痕迹，**一个不少**。

```text
在地牢生成新的层时，遵循以下原则：

（1）有主题 —— 雨林、火山、冰冻、魔瘴……每层一个，别重复。
（2）有一条或者几条前进路线，且**有明确的前往下一层的方式**
     （击破关底 / 满足某个条件 / 找到某条路）。
（3）有敌意单位、中立单位和友善单位，确保事件多样化而有挑战性。
（4）与上层连贯：越深越危险、越远离地表；不要连着三层同一个主题。
（5）参考主控当前的实力与状态 —— 别生成必死层，也别生成三只老鼠。
（6）一次别生成太多：玩家推进到哪一层，就长到哪一层。
```

> 第（1）(2)(3) 条是用户原话；(4)(5)(6) 是补的。
> **"通往下一层的方式"要写成结果，不写方式** ——
> 写「霜牙巨魔不再挡着那条路」，**不要**写「击败霜牙巨魔」。
> （玩家完全可能把它引走、或者用别的方式让它不再是障碍。）

### 生成器三 · 生成随机遭遇

**适用**：任何有行程的场合（走路、赶夜路、在城里晃）

**原则**：遭遇要跟「这地方为什么会有这东西」对得上。
**绝大部分遭遇是"世俗"的**：野狼、土匪、塌方、迷路、一个冻僵的旅人。
魔法的东西出现时**要有分量** —— 别拿它当路边的野怪。
配比大致三成麻烦、三成机会、四成只是风景（别每段路都有事）。

### 生成器四 · 生成新 NPC

**适用**：需要一个具体的人，而作者没点名时

**原则**：

1. **有戏的新角色以年轻女性为主** —— 主控是个年轻男人，「认识人」是这张卡的乐趣之一
2. 每个人给一个**具体到能记住**的特征：口音 / 疤 / 口头禅 / 一个怪癖 / 一门拿手的活
3. **她有自己的事要办**，不是站桩等玩家
4. **她想要什么，得说得出来** —— 写不出欲望的人，就是背景板
5. **人类里**会施法的人罕见，能熟练使的更罕见；精灵和龙族会一两手简单的，**但一样会累**
   —— 魔法出现时要有分量，别拿它当路边的野怪
6. **记得写种族** —— 默认是人类，但别让全镇清一色。
   **§2.2 那张表里只列了"见过的"五个 —— 需要就随手长新的**（魅魔、蜥蜴人、史莱姆娘……）

### 6.1 主控（玩家操控的那个角色）

| 段 | 字段 | 类型 | 初值 | 范围 | 谁写 |
| --- | --- | --- | --- | --- | --- |
| **固有** | 力量 · 敏捷 · 技巧 · 魔法 · 智力 · 魅力 | number | 3 | 1–10 | 角色 |
| **固有** | 种族 | string | 人类 | — | 角色 |
| **固有** | 本事 | 字符串列表 | `[]` | — | 角色 |
| **关系** | 关系 | 关系列表 | `[]` | — | 角色 |
| **携带** | 背包 | 物品列表 | 见开局 | — | 角色 |
| **当下** | 穿着 · 姿势 · 心情 | string | 见开局 | — | 角色 |
| **当下** | 伤势 | 字符串列表 | `[]` | — | 角色 |

> 顺序按**寿命**排：**固有 / 关系 / 携带 —— 这三段跨场景存活**；
> 「当下」是镜头里的那一层，**镜头一走就丢**（回头再由角色 agent 重新长出来）。

#### 「关系」是什么（2026-09-14 定）

**它是一段自然语言，不是数字。**（用户原话：*"倾向于不要有好感度数字，不然又要写规则"*）

```json
"关系": [
  {
    "对象": "{主控的名字}",
    "是什么": "队友",
    "经历": "在酒馆认识的。虽然觉得他不靠谱，但单靠自己很难探索地牢，所以勉为其难答应了组队。"
  }
]
```

| 字段 | 写什么 |
| --- | --- |
| `对象` | 对方的名字 —— **直接写名字，不要占位符**（主控的名字开局就定了） |
| `是什么` | **一个短标签**：队友 / 债主 / 点头之交 / 仇人 / 雇主 / 老主顾 |
| `经历` | **自然语言**：为什么是这个关系 |

> ⚠️ **`是什么` 不许写成数字** —— `"好感": 80` 是错的。
> 她要是不待见你，就写「点头之交」，然后在「经历」里写清楚为什么不待见。
>
> **每个角色条目都有这一段**（主控也有），两边描述的是同一件事，
> **同一次输出里一起写** —— 跟"背包转移要成对出现"是一个道理。

**六项属性各自管什么**（要写进提示词，否则判定 agent 分不清"敏捷"和"技巧"）：

| 属性 | 管什么 |
| --- | --- |
| 力量 | 扛、推、砸、近身硬碰 |
| 敏捷 | 躲、跑、跳、反应快慢 |
| 技巧 | 精细的手上活：开锁、扒窃、包扎、弓弩准头、剑术的细腻处 |
| 魔法 | 感知魔力、施法、抵抗法术、与魔法物品共鸣（**不是法力值，不消耗**） |
| 智力 | 记忆、推理、学识、看穿 |
| 魅力 | 说服、威慑、取信、谈判 |

> ⚠️ **没有等级、没有 HP、没有攻击力、没有经验值、没有技能等级、没有幸运。**
> 属性是"你是什么样的"，不是"你有多强"；伤势是"你哪伤了"，不是"你还剩多少"。

## 7. 开局

| 项 | 内容 |
| --- | --- |
| **起始时刻** | `2026-09-14T19:30`（傍晚）—— **只要卡自己自洽就行**，两种写法见下 |
| **初始位置** | 晨风镇 · 醉猫旅店 · 旅店大堂 |

**起始时刻的两种写法**（卡里写哪个都行）：

| 写法 | 含义 | 什么时候用 |
| --- | --- | --- |

## 8. 九个节点

**共同约定**：

- 每个节点的输出都是 **JSON 代码块**（沿用"文本协议 + JSON 代码块"的现有做法）
- **每个节点拿到的上下文完全一样**：从第 1 回合到现在的全部故事记录 + 当前世界状态 + 玩家这一轮的原话
  （用户 2026-09-14 定：先接受这个 token 成本；太长再加总结缩字数的机制）
- 决策层内部**没有"越权"一说**：大纲说"该有个铁匠"，后面的节点负责把它长出来

### ⓪ 精神分析

**职责**：给**玩家**（电脑前那个人，不是他操控的角色）建一份**画像**，
据此给这一轮的模拟定方向。
**不写故事、不碰世界状态、不判定成败** —— 你唯一能写的是「关于这位玩家」的那份画像。

**提示词要点**：

- ⭐ **你是全项目唯一读得到"玩家是谁"的节点** —— 别的节点只看得到世界，你只看得到人
- ⭐ **别写感想，做分析。用成熟的玩家研究框架，不要自己现编维度：**

| 维度 | 用什么 | 它决定什么 |
| --- | --- | --- |
| **人口学** | —— | 年龄 / 职业 / 经济 / 感情 / 居住。**他想看什么内容** |
| **动机** | **Bartle 玩家类型**（1996）：探索型 / 社交型 / 成就型 / 竞争型 | **该给他什么** |
| **心理需求** | **自我决定论（SDT）**：自主 / 胜任 / 关系 | **该怎么给** |
| **当下** | —— | 此刻的心情、精力、还剩多少时间 |

- **SDT 那三项怎么用**（这是最直接可操作的一层）：
  - **自主**高 → 多给选择，别替他做决定
  - **胜任**高 → 难度卡在"够得着，但要使劲"
  - **关系**高 → 多给能说话的活人
- **输入端有两样**：① 已有的画像（卡给的初值 + 你前几轮的补充）② 他这一轮**实际打下的那行字** ——
  措辞、长度、语气、他挑了什么动词，**全是信息**
- **你不告诉他你在分析他**
- **你的输出是给下面所有节点的「本轮总纲」** —— 它们全都读得到，一句话能拨动整轮的调子
- **其中也包括「这一轮该用什么笔法」**：作者在 §2.3 定了这张卡的**基线尺度**，你按这位玩家当下的状态往下拨

**输出**：

```json
{
  "画像补丁": {
    "人口学": { "年龄": "23", "职业": "计算机专业研究生", "经济": "靠奖学金，不宽裕",
                "感情": "单身，两个月前刚分手", "居住": "学校宿舍，双人间" },
    "动机": { "主": "探索型", "次": "社交型",
              "说明": "他连打了三个「看看」「往里走」—— 想逛，不想打" },
    "心理需求": { "自主": "高，讨厌被安排", "胜任": "中", "关系": "高，缺人说话" },
    "当下": "周五夜里，室友不在；这轮输入很短，像是不想动脑子" },
  "倾向": "别难为他。多给能逛的地方、能说话的活人；今晚别安排硬仗",
  "依据": "探索型 + 社交型；关系需求高而当下精力低 —— 他要的是在场感，不是挑战",
  "力度": "明显"
}
```

> 💡 **`画像补丁` 只在有新信息时才写** —— 大多数轮它该是空的，或者只动一两个字段。
> 每轮重写整份画像是浪费 token，**而且会让画像飘**（每次措辞都不一样，等于没记住）。

### ① 故事链

**职责**：维护**故事链** —— 这个世界里正在演的那些"完整的故事"。

两件事：① **维护现有的链**（到第几阶段、露过哪些线索）② **按需长出新链**。

**它是「地图 agent」的同构体：**

| | 维护什么 | 按需生成什么 |
| --- | --- | --- |
| 地图 agent | 区域 / 地点 / 谁在哪 | **新地点** |
| **故事链 agent** | 现有的链 | **新链** |

**提示词要点**：

- **一条链长这样** —— §4 的「将军与公主」就是第一条，它是**模板**，不是特例：

```json
{
  "名字": "将军与公主",
  "绑在": "地牢",
  "表层": "邪教徒掳走了公主，要献祭给邪神",
  "真相": "一位将军要政变，公主是唯一挡在路上的人",
  "核心冲突": "将军要她消失；公主手里有他的把柄",
  "阶段": ["听说悬赏", "发现教团是被人雇的", "查到雇主在宫里头", "见到公主"],
  "已露线索": ["教团仪式里有不合教义的地方"],
  "终点": "公主被救出 / 真相被揭开"
}
```

- ⚠️ **只有当玩家所在的地方没有活跃的链时，才长新的** —— 别见一个地方就长一条
- **规模要跟主线相当** —— 不能长出一条比「将军与公主」还大的
- **不能抢主线** —— 地牢那条永远是主菜
- **必须跟玩家所在的地方长在一起**（玩家在皇城，链就得是皇城里的事）
- ⭐ **链必须有「表层 / 真相」的落差** —— 那是它好看的唯一原因
- **线索一次露一条**，别急着揭穿（露哪条是大纲节点的活，你只负责记"露过哪些"）
- **大多数轮你是在空转的** —— 那就输出空的增改
- **别交代"总共几层"** —— 没人知道（见 §3 区域三）。你也只长玩家走到的那一层

**输出**：

```json
{
  "增改": [
    { "名字": "将军与公主", "阶段": 2,
      "已露线索": ["教团仪式里有不合教义的地方", "地牢里有一双好鞋"] }
  ],
  "新增": [],
  "说明": "玩家还在镇郊，这条链没推进"
}
```

### ② 行动判定

**职责**：判定玩家这一轮的行动**在这个世界里成不成、代价是什么**。
**不写故事，只下判断。** 判断要有依据 —— 依据是主控的属性、伤势、背包、当前场景，还有世界的物理法则（**中魔**）。

**提示词要点**：

- **不要总是成功，也不要总是失败。代价要具体。**
- 玩家可能做出这个世界里荒谬的事（比如"召唤一辆坦克"）—— 你要按**这个世界的法则**判它成不成立，
  而不是按"这是不是个好主意"

**输出**：

```json
{
  "可行": true,
  "结果": "部分成功",
  "依据": "主控技巧 4，锁是老式弹子锁；背包里有一截铁丝",
  "代价": "锁开了，但铁丝断在锁孔里 —— 这扇门下次从里面锁上就打不开了"
}
```

### ③ 故事大纲

**职责**：决定**这一轮演到哪儿为止**，并给出情节走向。
**它是第一个能看见"会发生什么"的节点** —— 场景和人物由它定，后面的节点负责长出来。

**提示词要点**：

- 只写"要发生什么"，**不写正文**（那是故事节点的事）
- **不要把耗时写死**（那是时间节点的事）
- 尽量**停在一个值得让玩家重新决策的位置**
- 用「需要长出来」把要新造的东西交给后面的节点 —— 别自己编细节
- ⚠️ **不许把主控演死**（见 §2.4）—— 致命的判定要落成**重伤 / 被俘 / 失去什么**，不是死亡

**输出**：

```json
{
  "本轮跨度": "从撬锁到他们下到地窖口，大约一刻钟",
  "情节": "锁开了。门后是向下的石阶，霉味混着铁锈味。玩家点起火折子往下走，走到一半听见底下有水声——不是滴水，是有人在搅水。阶尽头是一扇半开的木门。",
  "停在": "他伸手推那扇木门的前一刻",
  "需要长出来": [
    "地牢第 1 层「旧水窖」这个地点",
    "水声的来源：一个还活着的人，还是别的"
  ]
}
```

### ④ 时间

**职责**：判定**这一轮过了多久**。不改时间，只给推进量，引擎照着推。

**提示词要点**：

- 倾向：跨区域移动以**小时**记，跨地点移动**几分钟到十几分钟**
- **别当橡皮图章** —— 大纲写"追了三天三夜"你就顺着判三天，那你就白拿工资了。
  你的活是**把模糊的节拍翻译成具体时长，并让它跟世界对得上**（地图距离、天色、NPC 作息）
- 描述里的耗时是**基准，不是常量**：可以偏离，但**偏离要有理由**
- 你**不输出"现在几点"** —— 只给推进量；具体时刻和时段名由**引擎**算

**输出**：

```json
{
  "推进": { "step": 40, "unit": "minute" },
  "理由": "撬锁十几分钟，石阶走了十分钟，中间停下听动静。与上一轮的时刻衔接得上。",
  "备注": "如果玩家在下面耗太久，下一轮该提醒天色"
}
```

> ⚠️ **这里暴露了一个引擎缺口**：现有 `advance_time` 的单位只有
> `segment / hour / day / week / month / year`，**没有"分钟"**，而且**不允许"本轮不推进"**（拒 0）。
> 地牢爬行需要分钟级粒度 —— 见文末「附录 A」。

### ⑤ 地图

**职责**：维护世界的空间 —— 区域 / 地点 / 场景，以及**谁在哪**。

**提示词要点**：

- 只做两件事：① 把大纲「需要长出来」的东西**按生成器的原则**长出来 ② 更新「当前位置」与「谁在哪」
- **生成一次就冻结**：写进地图的东西之后**不许改**，只能补充细节
- 地图条目要带 **`来源`**（作者预设 / AI 生成）

**输出**：

```json
{
  "增改": [
    {
      "区域": "地牢",
      "地点": "第 1 层 · 旧水窖",
      "描述": "石阶尽头一扇半开的木门，门后是齐膝深的黑水，水面浮着碎木。",
      "来源": "AI生成"
    }
  ],
  "当前位置": { "区域": "地牢", "地点": "第 1 层 · 旧水窖", "场景": "木门外" },
  "谁在哪": [
    { "角色": "主控", "地点": "第 1 层 · 旧水窖" },
    { "角色": "萨伦", "地点": "晨风镇 · 萨伦铁匠铺" }
  ]
}
```

### ⑥ 角色

**职责**：维护**人** —— 主控与 NPC 的四段结构（固有 / 关系 / 携带 / 当下）。

**提示词要点**：

- **不在当前区域的角色，不要动他**（他"当下"那段可以丢，回头再长）
- **背包的增删必须在同一次输出里成对出现**：从 A 拿走，就一定要给 B 加上
- **关系两边一起写**：菲涅尔写「和主控：队友」，主控那边也要写「和菲涅尔：队友」
- 「本事」是**会什么**（"跟老猎户学过追踪"），**不是"多擅长"** —— 不写数值
- **种族写在「固有」里**，默认「人类」；只写种族名，别写一堆体质加成
- 「关系」写**标签 + 经历**，**不写数字**

**输出**：

```json
{
  "增改": [
    {
      "角色": "主控",

        { "对象": "菲涅尔", "是什么": "队友",
          "经历": "在醉猫旅店认识的。她嫌我不靠谱，但一个人下不了地牢。" }

            "固有": { "种族": "人类", "身份": "困在里面的采药人", "本事": ["认得草药", "会水"] },

      "携带": { "背包": { "新增": [{ "名称": "采药篓", "备注": "空了一半" }] } }
    }
  ]
}
```

### ⑦ 故事

**职责**：把上面所有的结论**写成正文**。

**提示词要点**：

- **你不改任何结论** —— 判定说成没成就是成没成，大纲说停在哪就停在哪，地图说门后是黑水就是黑水
- 人称：**第二人称**（"你"）
- 长度：**300–800 字**，看情节密度
- 写具体的东西：气味、声音、手感的细节。**别写数值**
- **时间是"世界内的说法"，不是钟点** —— 写「天已经黑透了」「火把还剩小半根」，
  **不要写「18:40」**（这个世界里的人没有表）

**输出**：

```json
{ "正文": "铁丝在锁孔里转到第三下的时候，咔哒一声……" }
```

### ⑧ 主 agent

**职责**：三件事 —— ① **一致性核对** ② **格式校验** ③ 交出一份可提交的状态。
**不创作、不改情节。**

**提示词要点**：

- 发现冲突时按「**结构事实优先**」处理：**已经冻结的世界事实不能被推翻**，
  要迁就的是新编的内容（大纲想让玩家遇到一个已经死掉的人 → 提示它换个人）
- 你产出的**合并结果由引擎写入**，你不直接改存档

**输出**：

```json
{
  "校验": { "通过": true, "问题": [] },
  "状态增改": ["……合并去重后的补丁，交给引擎写入……"],

    "时间": "2026 年 9 月 14 日 · 19:52",
    "场景": "地牢 · 第 1 层 · 木门外",
```

```text
┌──────────────────────────────────┬───────────────┐
│ 顶栏：时间 · 当前场景             │ 侧栏           │
├──────────────────────────────────┤  · 地图        │
```

| 区块 | 放什么 |
| --- | --- |
| **顶栏** | 时间 · 当前场景 |

> 侧栏从左边挪到了**右边**，故事区留在**左侧**。


**时段给氛围用**，**分钟不外显** —— 理由见附录 A 第 4 条。

## 11. 玩家（外部身份）

**这是「精神分析」读的东西，也是它唯一能写的状态。不显示给玩家。**

### 11.1 画像用什么框架（2026-09-14 定）

**不自己现编维度 —— 用现成的玩家研究框架：**

| 块 | 用什么 | 拿来干什么 |
| --- | --- | --- |
| **人口学** | —— | 年龄 / 职业 / 经济 / 感情 / 居住 → **他想看什么内容** |
| **动机** | **Bartle 玩家类型**（1996，MUD 时代最经典的分类）：探索型 / 社交型 / 成就型 / 竞争型 | **该给他什么** |
| **心理需求** | **自我决定论（Deci & Ryan）**：自主 / 胜任 / 关系 | **该怎么给** |
| **当下** | —— | 此刻的心情、精力、还剩多少时间 |

> ⭐ **为什么要在提示词里点名这些学术框架**：
> **点名 = 借用模型读过的全部相关文献。**
> 写"用 Bartle 分类"，模型就调出它知道的关于探索型玩家的一切；
> 写"SDT 的自主需求高"，它就知道该多给选择而不是多给奖励。
> **一个学术名词，省掉十行解释。**

### 11.2 初值（卡作者写的）

```text
你的玩家是一位男大学生，坐在自己宿舍的电脑前，
想玩一个自由又有趣的游戏来放松一下心情。
请你把故事往满足他的需求的方向模拟。
```

> ⚠️ **只有这一段是作者写的。** 之后每轮由「精神分析」补充、修正（它写 `画像补丁`）——
> 所以这份画像会**越来越准**：玩得越久，它越知道这位玩家到底想要什么。
>
> 这也是为什么它**不显示给玩家**：它是模型的判断依据，不是玩家的属性面板。

# 附录 A：写这张卡时发现的四个引擎缺口

> **这些不解决，卡跑不起来。** 都属于"改引擎"，不是"改卡"。

| # | 缺口 | 说明 | 怎么改 |
| --- | --- | --- | --- |
| 1 | **时间引擎没有"分钟"** | 现有单位是 `segment / hour / day / week / month / year`；地牢爬行需要分钟级 | 加 `minute` 单位 |
| 2 | **`step` 会被悄悄取整** | `advanceTime` 里有 `Math.round(raw)` —— 连 `step: 0.5` 都会被抹成 1 | 跟第 1 条一起处理 |
| 3 | **不允许"本轮不推进"** | `advanceTime` 对 `n <= 0` 直接报错（那是拦模型错误输入的） | 允许显式的 no-op（"这一轮只有几秒"） |
| 4 | **时段只有 3 段** | `calendar.js` 的 `SEGMENTS` = `上午 / 下午 / 晚上` —— **分不出"深夜"和"凌晨"**，而地牢爬行正需要 | 扩成下面 8 段（引擎内置） |

## 8 个时段（2026-09-14 定）

| 段 | 小时 | | 段 | 小时 |
| --- | --- | --- | --- | --- |
| **凌晨** | 01:00–04:59 | | **傍晚** | 17:00–18:59 |
| **清晨** | 05:00–07:59 | | **入夜** | 19:00–21:59 |
| **上午** | 08:00–10:59 | | **深夜** | 22:00–00:59 |
| **正午** | 11:00–12:59 | | | |
| **下午** | 13:00–16:59 | | | |

> **玩家看不到小时**，只看到「入夜」「深夜」这样的名字。
>
> **为什么显示层不给分钟**：① 模型判的"40 分钟"本来就是**估的**，显示成 `19:52` 是**假精确**；
> ② 世界里的人没有表，说"七点五十二分"出戏；
> ③ **地牢里失去时间感是这个题材最好的张力之一** —— 侧栏挂着精确时刻，这份张力当场归零。

# 附录 B：卡的存储格式（已定，2026-09-14）

## 存 JSON

理由只有一条，但它决定性地解决了这个纠结：

> **作者不手写卡文件。** 将来游戏里会有一个「做卡界面」，作者在 textarea 里写提示词，
> 多行、不用转义、不用管引号 —— **他永远看不到那个 JSON**。

所以格式该为**引擎**优化，而不是为手感服务：

| 为什么选 JSON | |
| --- | --- |
| **零依赖** | 浏览器原生 `JSON.parse` / `JSON.stringify`，不用引解析器 |
| **`git diff` 干净** | 提示词**按行存**（字符串数组），改一行只显示一行 |
| **表达力够** | 卡里有树（区域 → 地点）、有表（状态字段），JSON 天然表达得了 |

**分享方式**：导出成**单个 `.json` 文件** → 别人「导入卡」→ 玩。
**一张卡 = 一个自包含的文件** —— 这就是"既能做卡又能玩卡"的闭环。

> 但它既然已经定了，卡的格式就不用再为"作者手写舒不舒服"妥协了。
